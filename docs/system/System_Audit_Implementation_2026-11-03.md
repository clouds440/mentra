# System audit implementation and acceptance — 2026-11-03

The documented audit gaps are implemented with regression and comparative evidence. The changes remain a local source implementation until migration and deployment are performed. No live LLM, Cloudinary or production-database calls were made. Cached local models were exercised on CPU.

Baseline: `c3f05376f96e8b3573daa3064dcf510f1a944c66`. See the preserved [findings register](history/Audit_Findings_2026-11-03.md), [evidence index](verification/README.md) and [integrity manifest](verification/manifest.json). Earlier library/BGE/E5 reports are untouched: older model results are not relabelled as current E5 evidence.

## Local model coverage and policy

| Local model | Device backend | Preserved CPU behavior | Recovery boundary |
| --- | --- | --- | --- |
| E5 embeddings | PyTorch | Same model/revision, float32, dimension, E5 role prefixes and validation. | Serialized model wrapper and supervised child. Separate cold initialization budget remains intact. |
| Cross-encoder reranker | PyTorch | Same model/revision, float32, windows/budgets and score order. | Serialized wrapper and supervised child under original cold/warm request deadline. |
| Whisper Base | CTranslate2 | INT8, beam 3, two CPU threads. | Fully consume segments before publishing; discard failed partial output and replay once on CPU. Supervised native exit recovery remains within the original request deadline. |
| Silero VAD | ONNX Runtime | Same upstream segmentation and CPU session. | Replace only session adapter; verify selected CUDA provider actually initialized, otherwise use CPU. |
| Tesseract OCR | CPU-only | Existing subprocess and OCR behavior. | Explicit CPU-only choice; no unsupported CUDA flags. |

`LOCAL_INFERENCE_DEVICE=auto|cpu|cuda` controls compatible local inference. `EMBEDDING_DEVICE` can override embeddings; `auto` inherits the global choice. `cuda` is a preference with CPU fallback, not a requirement. Default runtime packages may be CPU-only; the utility cannot add missing accelerator drivers/libraries. This change does not modify CUDA images or deployment hardware. CPU fallback is sticky for the model/worker lifetime; normal process restart reprobes availability. Inference callbacks are pure with respect to domain writes, so retries cannot duplicate assessment/evidence publication.

## Verification and limitations

The final combined backend run passed **323 tests in 323.166 seconds**. Nine answer-sheet and five voice browser tests passed; TypeScript/Vite, Ruff and theme/UI checks passed. Native recovery checks, browser runs, static checks and build logs are indexed with their actual outcomes in [verification/README.md](verification/README.md). Intermediate failures remain preserved and explicitly superseded. Current evidence uses the cached `mentra-backend:embedding-finished-20261103` dependency image with current backend source mounted read-only; it is not a claim that a new release image was deployed. Database tests use isolated schemas in a disposable PostgreSQL 17 container. Frontend browser APIs are fixtures; backend database tests cover domain ownership and writes separately.

No physical CUDA hot-unplug, CUDA-output equivalence, GPU throughput, live provider calls, full production load, production deployment or exhaustive speech-language accuracy evaluation was run. Exception/lazy/native-exit simulations establish recovery logic only. Admission is a capacity bound, not priority scheduling; global/owner capacity of one cannot guarantee interactive headroom. Lower beam size, smaller speech model, forced-language decoding, quantized embeddings, a changed reranker and increased inference concurrency were **not adopted**, because this run supplies no quality/performance evidence to justify them. Existing model assets and historical BGE/E5 comparisons remain unchanged.

## Rollout and rollback

| Step | Action / acceptance condition |
| --- | --- |
| Prepare | Back up PostgreSQL, preserve private originals and existing model manifests. Stage the coordinated backend/frontend release. Keep the preceding release artifact. |
| Migrate | Apply Alembic through **`20261103_0040`** before starting the new application. It adds `assessment_source_job` and nullable `file_speech_operation.request_hash`; existing canonical attempts, answers, grades, original files and legacy speech receipts remain intact. Old migrations are unmodified. |
| Configure | Use `LOCAL_INFERENCE_DEVICE=cpu` to retain explicit CPU operation, or `auto` to probe installed compatible backends. Verify the embedding override as well. No reindex is required for a device-only change. |
| Start | Start assessment, RAG, summarizer, events and Files workers with the API. The assessment worker now also consumes source jobs. Check `/health/ready` queue diagnostics and operation-specific failures; idle queues are not proof that a worker exists. |
| Smoke | Use owned synthetic records: normal/chat upload -> queued/read/review -> confirmed submission; voice direct -> replay; RAG retry -> fresh document list; background reminder -> badge; completed chat -> one evidence job. Check original-file access and namespace selection. Live provider smoke checks require the deployment environment and were not performed here. |
| Observe | Monitor source age/leases, WORK_CAPACITY deferrals, inference fallback, speech timeout, reranker degradation and Files cleanup. A live lease can mask a stalled job until expiry; a heartbeat proves polling, not outcome correctness. |
| Roll back code | Stop new admission, drain queued/running source jobs and automatic retries, then stop workers. Revert backend/frontend together. Keep schema 0040 while returning to old code where possible; the additive schema preserves canonical data. Reconcile manual retry work before removing its job history. |
| Downgrade schema if necessary | After drain and backup, downgrade to 0039. The migration refuses queued/running jobs. It drops only the new job table and new request-hash column; canonical attempts/files are retained. New binaries require 0040 and must not run against the downgraded schema. The roundtrip/drain guard is tested. |
